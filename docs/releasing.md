# Выпуск AdmiralRadzen

## Версии

Пакеты `AdmiralRadzen.Icons`, `AdmiralRadzen.Themes` и `AdmiralRadzen.Components` версионируются независимо по SemVer 2.0.0. Номер в `<Version>` проекта — версия соответствующего NuGet-пакета:

- PATCH: совместимое исправление или изменение ассетов без нового публичного поведения.
- MINOR: совместимое расширение возможностей или публичного API.
- MAJOR: несовместимое изменение API или поведения.
- Предварительная версия: суффикс `-preview.N` (или `-rc.N`) у конкретного пакета; стабильную версию с тем же номером публикуют отдельно.

Версия опубликованного пакета неизменна: повторная сборка с тем же номером не заменяет файл на nuget.org. Документация или CI сами по себе не требуют повышения версии пакета. Перед выпуском сравните API, состав пакета и зависимости с последней опубликованной версией.

`Components` указывает точные версии `Icons` и `Themes`. При выпуске новой версии одного из этих пакетов проверьте, требуется ли новый `Components` с обновлённой зависимостью; если требуется, повысьте его версию и публикуйте после зависимостей. Не меняйте идентификаторы пакетов, пространства имён и пути `_content` при обычном повышении версии.

## Ветки и проверки

Рабочие ветки и pull request создаются от `main`; постоянной ветки `develop` нет. CI pull request должен завершиться успешно до объединения. Выбирайте дополнительные локальные проверки по затронутым областям и фиксируйте непроверенные сценарии в pull request. Объединяйте squash commit и удаляйте ветку.

## Порядок выпуска

1. Подготовьте PR с необходимыми версиями, зависимостями и release notes; проверьте содержимое NuGet-пакетов, лицензии и notices.
2. После успешного CI объедините PR в `main`. Зафиксируйте SHA коммита и результаты CI.
3. Выпустите нужные пакеты через Trusted Publishing. Проверяйте версии на nuget.org; публикуйте зависимости раньше `Components`.
4. Создайте один аннотированный тег `release-YYYY.MM.DD.N` на проверенном коммите и один GitHub Release с **точными версиями** опубликованных пакетов. Дата тега обозначает согласованный снимок репозитория, а не SemVer пакета. Не переносите опубликованный тег.

Первый публичный снимок: [`release-2026.10.22.1`](https://github.com/irlyk/admiral-radzen/releases/tag/release-2026.10.22.1) — Icons 1.0.3, Themes 1.1.2, Components 1.2.2.

Текущий `.github/workflows/publish-nuget.yml` закрепляет имена файлов именно этих трёх версий и публикует все три пакета. **Не запускайте его повторно для следующего выпуска без отдельного изменения workflow:** сначала замените закреплённые версии, определите состав выпуска и проверьте, что эти версии ещё не опубликованы. Публикация и создание GitHub Release выполняются только по решению владельца.
