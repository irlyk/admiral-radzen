# Стиль кода компонентов

Ориентир — структура исходников Radzen.Blazor: разметка Razor и соседний
частичный C#-класс. Сохраняем файловые пространства имён и публичные
контракты Admiral.

## Ответственность файлов

- `Admiral*.razor`: разметка, шаблоны и привязки DOM-событий. Повторяющиеся
  участки разметки можно оформлять именованными Razor-фрагментами.
- `Admiral*.razor.cs`: параметры, состояние, жизненный цикл, вычисляемые
  свойства и обработчики. Атрибуты параметров — отдельными строками.
  При рефакторинге сохраняем имена, значения по умолчанию, события и
  ограничения обобщённых типов.
- Дополнительный partial-файл выделяется для самостоятельной существенной
  задачи. Например, `AdmiralDataGrid.RowReorder.cs` содержит перестановку
  строк мышью и клавиатурой и управление соответствующим JS-подключением.
- `Internal/`: общие детали реализации и логика, независимая от разметки.
  `AdmiralTreeSelectItems` — обход дерева и каскадный выбор,
  `AdmiralComboBoxInterop` — подключение браузерных событий.
- `Models/`: публичные контракты Admiral. Новый параметр не должен
  раскрывать тип Radzen только ради сокращения реализации.

Маленькие обёртки могут оставлять короткий блок `@code`.
Разделяем по ответственности, а не по числу строк. Не создаём базовые классы
или сервисы для несвязанных компонентов из-за пары похожих свойств.

## Соглашения

Используем понятные имена, явные модификаторы доступа и фигурные скобки.
Короткое вычисление или делегирование можно записать выражением.
Многошаговые переходы состояния и освобождение ресурсов — обычными блоками.
Для нового публичного API нужна XML-документация поведения и значений по умолчанию.

Для статической разметки предпочитаем Razor-шаблоны ручному
`RenderTreeBuilder`. Выбор, раскрытие и события остаются в C#;
JS — для браузерных операций, например условного `preventDefault`
или управления фокусом.

Не пересобираем коллекцию при каждом чтении свойства за один рендер.
Производные данные обновляем при изменении параметров и локального состояния.
Нельзя полагаться только на равенство ссылок: потребитель может изменить
элементы существующего списка перед повторным рендером.

Оформление остаётся в теме. Рефакторинг не повод дублировать состояния
focus, hover и disabled в изолированном CSS компонентов.

## Проверка

Собираем пакеты и решение по [инструкции](../README.md#сборка-и-запуск).
Обновляем пакеты smoke и перезапускаем сервер. При рефакторинге проверяем
затронутые события, шаблоны и клавиатуру в обеих темах, запускаем существующие
[регрессионные проверки](radzen-regression.md).
Публичные контракты и DOM-структура должны сохраняться, если изменение поведения
не было отдельной задачей.
